# C 라이브러리 함수 공부용 부록 디자인

## 목적

기존 4장짜리 2분 발표 자료 뒤에 과제에서 실제로 사용한 외부 라이브러리 함수 16종을 함수별로 학습할 수 있는 부록을 추가한다.

## 산출물

- 기존 발표 슬라이드 4장 유지
- 공부용 부록 16장 추가
- 총 20장
- 기존 네이비, 아이보리, 민트, 코랄 디자인과 Pretendard, Consolas 글꼴 유지
- 원본 PPTX는 보존하고 새 파일명으로 저장

## 대상 함수

1. `strchr`
2. `strcmp`
3. `strlen`
4. `strcpy`
5. `strncpy`
6. `memcpy`
7. `memset`
8. `strtok`
9. `malloc`
10. `realloc`
11. `free`
12. `printf`
13. `snprintf`
14. `perror`
15. `exit`
16. `strdup`

## 함수별 슬라이드 구조

각 부록 슬라이드는 같은 정보 순서를 사용한다.

1. 함수명과 이름을 이해하기 위한 풀이
2. 필요한 헤더와 표준 구분
3. 함수 원형
4. 각 인자에 넣는 값
5. 반환값과 실패 표현
6. 내부 동작을 초보자가 이해할 수 있는 한 문장
7. 안전한 짧은 코드 예제
8. 확인하지 않았을 때 생기는 위험
9. 과제에서 실제 등장한 번호

## 정확성 기준

- 함수명의 풀이는 공식 약어라고 단정하지 않고 `이름 읽기`로 표기
- `strchr`는 복사나 목적지 크기 검사를 하지 않고 검색 실패 시 `NULL`을 반환
- `strcmp` 결과는 음수, 0, 양수로만 해석
- `strlen`은 널 문자를 제외한 길이를 반환
- `strncpy`는 원본이 길면 널 문자를 붙이지 않을 수 있음
- `memcpy`는 겹치는 영역에 사용할 수 없으며 겹치면 `memmove`가 필요
- `memset`은 바이트 단위로 값을 채움
- `strtok`은 원본 문자열을 변경하고 내부 상태를 사용
- `malloc` 메모리는 초기화되지 않으며 실패 시 `NULL`
- `realloc` 성공 시 기존 주소와 내부 포인터가 무효가 될 수 있고 실패 시 기존 블록은 유지
- `free(NULL)`은 안전하지만, 할당 시작 주소만 한 번 해제
- `printf`의 형식 지정자와 실제 인자 타입이 일치해야 함
- `snprintf` 반환값이 버퍼 크기 이상이면 출력이 잘림
- `perror`는 현재 `errno`를 출력하므로 오류 직후 사용
- `exit`는 표준 스트림 정리와 `atexit` 처리 후 프로세스를 종료
- `strdup`은 과제 환경에서 POSIX 함수이며 반환 메모리는 `free`해야 함

## 시각적 밀도

- 부록은 발표하지 않고 개인 학습에 사용
- 슬라이드 제목 32pt 이상, 본문 18pt 이상, 코드는 19pt 이상
- 긴 문단 대신 짧은 정의와 코드 예제를 사용
- 위험 조건은 코랄 색상으로 분리
- 코드와 설명이 겹치지 않도록 좌우 2단의 평면 구성을 사용

## 검증

- 총 20장인지 확인
- 기존 4장의 내용과 발표자 노트가 유지되는지 확인
- 16개 함수가 각각 정확히 한 장씩 존재하는지 확인
- 모든 부록 슬라이드를 렌더링해 글자 잘림과 겹침을 검사
- 최종 PPTX를 재가져오기 해 구조 손상 여부를 검사
