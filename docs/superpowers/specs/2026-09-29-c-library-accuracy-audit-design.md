# C 라이브러리 발표 자료 정확성 교정 설계

## 기준

과제 Makefile의 `-std=c11`과 Challenge 12의 `_POSIX_C_SOURCE 200809L` 설정을 기준으로 한다. ISO C 함수는 WG14 N1570의 C11 라이브러리 규격, `strdup`은 POSIX 규격에 맞춰 설명한다.

## 변경 범위

### 슬라이드 1

자료 전체에 POSIX 함수인 `strdup`이 포함되므로 오른쪽 하단의 `표준 라이브러리 함수`를 `C 표준·POSIX 라이브러리 함수`로 변경한다.

### 슬라이드 2

- 제목을 `포인터 반환값과 NULL`로 변경한다.
- 관련 함수에서 `strcmp`를 제거하고 `strdup`을 추가한다.
- `NULL`의 의미를 다음과 같이 구분한다.
  - `strchr`: 문자를 찾지 못함
  - `strtok`: 다음 토큰이 없음
  - `malloc`, `realloc`, `strdup`: 메모리 할당 실패
- 발표자 노트도 같은 구분을 설명하도록 수정한다.

### 슬라이드 3~5

내용을 재검토했으며 사실 교정이 필요하지 않다. 현재 내용과 디자인을 유지한다.

### `strcmp` 함수 슬라이드

`사전식으로 비교한다`를 `각 바이트를 unsigned char 값 기준으로 앞에서부터 비교한다`로 수정한다. 반환값은 정확히 `-1`이나 `1`이 아니라 음수·0·양수라는 기존 설명을 유지한다.

### `realloc` 함수 슬라이드

- `ptr`은 동적 할당 블록의 시작 주소 또는 `NULL`이라고 명시한다.
- `ptr == NULL`이면 `malloc(new_size)`처럼 동작한다고 설명한다.
- 실패하면 기존 블록이 유지된다는 설명을 유지한다.
- 성공하면 이전 블록의 수명이 끝나므로 기존 포인터와 내부 포인터를 다시 사용하면 안 된다고 명시한다.
- `new_size == 0`은 이 자료의 안전한 사용 예에서 제외하고 피하도록 한다.

### `exit` 함수 슬라이드

운영체제의 메모리 회수 여부로 오해할 수 있는 `지역 메모리를 직접 free해 주지 않는다` 문장을 제거한다. 다음 내용으로 교체한다.

> exit를 호출한 뒤의 코드는 실행되지 않는다. 라이브러리 함수에서 호출하면 호출자가 오류를 복구하거나 필요한 정리를 수행할 기회를 잃는다.

## 유지 사항

- 전체 21장과 기존 디자인을 유지한다.
- 슬라이드 3·4·5의 화면과 발표자 노트는 변경하지 않는다.
- 함수 분류와 색상 순서는 변경하지 않는다.
- 수정하지 않는 함수 슬라이드는 현재 원형·인자·반환값 설명을 유지한다.

## 검증 기준

- 슬라이드 2의 관련 함수가 `strchr`, `malloc`, `realloc`, `strtok`, `strdup`이다.
- 슬라이드 2에 `strcmp`가 없다.
- 슬라이드 3·4·5의 렌더링 해시가 이전 버전과 동일하다.
- 함수별 슬라이드 순서와 색상은 이전 버전과 동일하다.
- 전체 21장에 텍스트 잘림과 겹침이 없다.
- 패키지, 레이아웃, 폰트 검사를 통과한다.
